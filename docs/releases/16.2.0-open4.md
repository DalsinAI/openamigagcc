# GFOpenAmigaGCC 16.2.0-open4

GCC 16.2 for AmigaOS 3.x (`m68k-amigaos`). Everything in open3 remains. Open4 adds the wrong-code and libnix fixes merged since open3.

## New since open3

| Item | open3 | open4 |
| --- | --- | --- |
| `move.b (a2)+,(a0,a2.l)`: a move whose source steps a register addressed its destination through it (GCC 15's late-combine, PR123853) | each element landed one place late at `-O2` | never generated: `patches/gcc/0013` ([docs](../autoinc-move.md)) |
| `strcat` into a local array, inlined at `-O1`/`-O2` for 68020 and up | wrote to an absolute address (`virtual-stack-vars` left after vregs) | addresses the array: `patches/gcc/0014` ([docs](../vregs-address.md)) |
| `strtol`/`strtoul` on empty or whitespace-only input | left `endptr` unset | `endptr` is the input: `patches/libnix/0008` ([docs](../libnix-strtol-endptr.md)) |
| Compiler identity | `GFOpenAmigaGCC 16.2.0-open3` | `GFOpenAmigaGCC 16.2.0-open4` |

## Checked with

The release is built and published by this repository's `build` workflow (run by hand with `release: 16.2.0-open4`). The tarballs are published only if every check in that same run passes:

- A complete build from `scripts/sources.lock` with every patch, and `build.sh`'s own checks: the open4 identity, no `libm881` for soft-float `-m68040`, no `trap #7` for a read of address 0, C and C++23 programs link with libnix.
- `tests/repro/prove.sh`, plain and with `-fno-tree-loop-distribute-patterns`, under `qemu-m68k`, including the 0013 and 0014 reproducers.
- `tests/libnix/endptr/run.sh`: the built libnix's `strtol`/`strtoul` end pointers under `qemu-m68k`.
- `tests/cxx/lean-check.sh` and `tests/baserel/eh-check.sh`.
- A compile of the tests that need a real AmigaOS (`tests/cxx`, `tests/pthreads`, `tests/libnix`); running them stays a lab job.
- `scripts/package.sh`: no NDK file in either tarball, and every `libamiga.a` is GFOpenNDK's.

## Known

- The toolchain needs glibc 2.38 or later.
- The shared `libnix4.library` still does not link; normal static programs do not need it.
- For ARM64 Linux, use 16.2.0-open1's toolchain until an ARM64 build of open4 is made.
