# GFOpenAmigaGCC 16.2.0-open2

GCC 16.2 for AmigaOS 3.x (`m68k-amigaos`), built from main at 97f54b9. Everything in 16.2.0-open1 is still here. This release adds the thread and C++ fixes the Team found while building the GFOpen family, along with the NDK inline fix.

## New since open1

| Bug | open1 | open2 |
| --- | --- | --- |
| A library call nested in another's arguments, such as `Stricmp(FilePart(x), ...)`, ran the outer call with the inner library's base in A6. The NDK's `inline/*.h` headers made by sfdc had this bug. | wrong base at -O1, -O2 and -Os | right: the recipe fixes sfdc and the installed headers |
| A thread that was running when a later thread was created read freed memory as it ended. C++ `thread_local` or `call_once` in several threads crashed (80000003, 80000006) or hung the machine. | crash or hang | right (libpthread) |
| `pthread_detach` was a stub, a detached thread's slot was never given back, and `pthread_join` errors left its semaphore held. | `std::thread::detach` threw | right (libpthread) |
| `pthread_join` busy-waited and changed its own priority by hand. | busy wait | it now waits for a signal |
| `__sync_val_compare_and_swap` returned the wrong value. | wrong | the old value, as GCC's builtin returns |
| A `thread_local`'s destructor never ran. | never ran | runs: `-fuse-cxa-atexit` is the default, and libnix has `__cxa_atexit` and `__dso_handle` |
| C++ streams formatting numbers in several threads at once hung (libnix `setlocale()`). | hang | right |
| Soft-float doubles were rounded to single precision on an Amiga with an FPU, because OS 3.2's IEEE libraries set FPCR. | wrong | right |
| Base-relative C++ (`-fbaserel`, `-fbaserel32`, `-resident`, `-resident32`): startup read its lists through A4, new threads had no A4, and catch-by-type failed to link ("LDFCM ... out of range"). | did not link or hung | links, starts, runs threads and catches by type |

Also new: a lean C++ profile for libraries, with a check (`tests/cxx/lean-check.sh`), and CI that builds the toolchain and runs the reproducers on every pull request.

## Checked with

- CI on 97f54b9: the toolchain builds; every `tests/repro/prove.sh` line is right, including `nested` at -O1, -O2 and -Os; `tests/baserel/eh-check.sh` is right.
- The release build itself: a clean build into a fresh prefix, `prove.sh` and `eh-check.sh` right.
- AmigaOS 3.2 on a 68040 (lab): amigachrome-stoves' os32-gcc16 qualification passed 32 of 32 tests, built with this toolchain. That covers exceptions, RTTI, threads, atomics, the FPCR test, GFOpenTLS's vectors at 020 and 060, thread safety t11 to t19, and t18's streams. t3, t3race and t3w each passed 20 of 20 runs, with no hang.

## Install

Unpack, put `bin/` on `PATH`, and add the AmigaOS 3.2 NDK with `scripts/install-ndk.sh` from the source release (see `docs/install.md`). The installer applies the nested-call fix to the NDK's inline headers. The NDK, Roadshow's network headers and the AHI and CyberGraphX developer headers are not included.

The x86-64 toolchain uses the host's GMP, MPFR and MPC at run time: install `libgmp10`, `libmpfr6` and `libmpc3` (Debian and Ubuntu names; most systems with a GCC already have them). They are not part of either tarball.

## Known

- The toolchain needs glibc 2.38 or later.
- The shared `libnix4.library` still doesn't link. Static programs, the default, don't need it.
- Code written for GCC 6.5 may stop with `-Werror` on GCC 16's newer warnings and errors.
